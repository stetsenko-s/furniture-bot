# Мебельный бот

Отдельный Telegram-бот для сценария:
**рукописный эскиз → уточнения → эскиз → утверждение → размеры → утверждение → рендер → утверждение**.

Обычные сообщения уточняют текущий этап. Кнопка «Назад» возвращает на предыдущий;
старые результаты доступны в «Чертежах». [Проверка новой последовательности](docs/workflow-testing.md).

Бот раскроя в соседней папке «ТГ бот распил» работает отдельно.
Здесь не меняются его код, токен, калькулятор или опубликованный сайт.

## Что уже работает

- Приём текстовых сообщений, фотографий и файлов JPG/PNG/WebP до 10 МБ.
- Диалог с пониманием изображений через OpenRouter или прямой OpenAI API.
- Сохранение проектов, сообщений, фотографий и версий в SQLite.
- Проекты «Проект №1», «Проект №2» и далее; переименование без обращения к GPT.
- Кнопки «Удалить», «Назад», «Переименовать»; удаление с подтверждением.
- «Данные изделия» и «Чертежи» после появления результатов.
- Ответ на новый текст или эскиз появляется ниже сообщения пользователя;
  кнопки и обновления обработки редактируют текущую карточку без новых сообщений.
- Создание черно-белого эскиза отдельным HTTP-микросервисом.
- Уточнения обычными сообщениями после результата и во время обработки.
- Новая версия требует нового подтверждения. Старые изображения сохраняются.
- Ошибка API не удаляет введённые данные; анализ можно повторить.

Нанесение габаритов и внутренних размеров, их исправление и рендеринг реализованы
отдельными сервисами. Неизвестные размеры запрашиваются в чате.
Инженерная проверка конструкции, деталировка, передача в калькулятор и КП
ещё не реализованы. Генерация размерных линий нейросетью требует проверки:
программная проверка входных чисел не гарантирует правильность подписей на изображении.
Первый результат — эскиз для согласования, а не производственный чертёж.

План будущих сервисов: [docs/roadmap.md](docs/roadmap.md).
Результаты проверки кода и приоритеты доработки: [аудит от 19 октября 2026](docs/code-review-2026-10-19.md).

## Запуск на Windows

Требуется Python 3.13. Откройте **эту папку** как отдельный проект в PyCharm.
В терминале PowerShell из этой папки:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

Скрипт создаст отдельное окружение `.venv`, установит зависимости и подготовит
`.env`. Если настройка уже выполнена, он сохранит существующий `.env`.

Откройте `.env` и укажите новый токен Telegram и настройки OpenRouter:

```dotenv
FURNITURE_BOT_TOKEN=токен_нового_бота
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=ваш_ключ_OpenRouter
OPENROUTER_DIALOGUE_MODEL=openai/gpt-4.1-mini
OPENROUTER_SKETCH_MODEL=openai/gpt-image-2
```

1. В @BotFather создайте **нового** бота командой /newbot.
2. Полученный токен укажите в FURNITURE_BOT_TOKEN.
3. Создайте аккаунт и API-ключ OpenRouter, пополните его баланс.

Пошагово: [подключение OpenRouter](docs/openrouter.md). При таком выборе
пополнять баланс OpenAI отдельно не требуется. Для прежнего прямого API
укажите AI_PROVIDER=openai и OPENAI_API_KEY. Существующий `.env` без AI_PROVIDER
продолжает работать через OpenAI; переключение нужно указать явно.

Ключи остаются в локальном `.env`, который исключён из Git и Docker-образов.
Четыре внутренних ключа *_SERVICE_TOKEN создаются
автоматически. При обновлении существующего проекта один раз выполните
`python configure.py`: он добавит недостающий внутренний ключ и сохранит
ваши токены и настройки моделей. Базы и картинки переносить не нужно.

В первом терминале:

```powershell
.\.venv\Scripts\python.exe run_dialogue.py
```

Во втором терминале:

```powershell
.\.venv\Scripts\python.exe run_sketch.py
```

В третьем и четвёртом терминалах соответственно:

```powershell
.\.venv\Scripts\python.exe run_dimensions.py
```

```powershell
.\.venv\Scripts\python.exe run_render.py
```

В пятом терминале:

```powershell
.\.venv\Scripts\python.exe run_bot.py
```

В PyCharm выберите интерпретатор `.venv\Scripts\python.exe` **этого проекта**
и создайте пять конфигураций: run_dialogue.py, run_sketch.py, run_dimensions.py, run_render.py, run_bot.py.
Рабочая папка всех конфигураций — корень этого проекта.

Параметры конфигурации бота в PyCharm:
- Script path: `C:\Users\User\Desktop\Мебельный бот\run_bot.py`.
- Python interpreter: `C:\Users\User\Desktop\Мебельный бот\.venv\Scripts\python.exe`.
- Working directory: `C:\Users\User\Desktop\Мебельный бот`.

Если запустить bot/main.py напрямую, он автоматически передаст управление
run_bot.py. Менять интерпретатор или вручную добавлять PYTHONPATH не нужно.

Откройте нового бота в Telegram, отправьте /start.
Пока все пять процессов работают, бот доступен. Закрытие терминала, выключение
или сон компьютера прекращают обработку новых сообщений; проект сохраняется.
Для постоянной доступности позже потребуется постоянно включённый сервер.

Проверка локального сервиса:

```powershell
Invoke-RestMethod http://127.0.0.1:8092/health
Invoke-RestMethod http://127.0.0.1:8091/health
```

Этот запрос не вызывает OpenAI и не генерирует изображение.

## Пользовательский сценарий

1. /start → «Новый проект».
2. Отправить рукописный эскиз, описание изделия и известные размеры.
3. Ответить на уточнения. Размеры в описании проекта сохраняются в миллиметрах.
4. Проверить описание. Написать исправления, если нужны.
5. Нажать «Подтвердить и создать чертёж».
6. Получить черно-белый эскиз.
7. Написать, например, «Добавь полку» — бот продолжит тот же проект.
8. Снова проверить описание и подтвердить генерацию новой версии.

Повторное нажатие на подтверждение готовой версии возвращает сохранённый
результат. Уточнения во время генерации сохраняются сразу, а старый результат
прикрепляется к своей версии. Для нового изделия используйте «Новый проект».

Открытие проекта показывает текущие данные и последний сохранённый чертёж,
если он есть. Далее можно сразу писать уточнения. «Назад» из карточки возвращает
к списку проектов; из истории и переименования — к карточке.

«Переименовать» → написать название в одной строке (1–100 символов).
Название не изменяется моделью; переименование не создаёт версию изделия.
Нумерация отдельная для каждого пользователя. Новый номер — максимальный
среди оставшихся проектов плюс один, включая переименованные. Например,
после удаления «Проект №2», если остался только №1, новый снова будет №2.
После удаления всех проектов нумерация начинается с №1.
При обновлении старые проекты «Новый проект» получают порядковые номера;
существующие собственные названия и данные сохраняются.

Размеры вводятся обычным сообщением в чате открытого проекта, например:
«Ширина 1000 мм, высота 800 мм, глубина 500 мм». Для правки одного размера:
«Измени высоту на 900 мм». Пример виден при создании проекта и в его данных.
Отдельных полей формы нет; размеры из текста разбирает существующий LLM-диалог.

«Удалить» → подтверждение «Удалить» или «Отмена». Бот удаляет свой проект,
историю, исходные файлы и сохранённые результаты. Поздний ответ модели
не восстанавливает удалённый проект. Уже начатый запрос к внешнему API
может завершиться; отдельный кэш сервиса sketch и старые сообщения Telegram
этим действием не очищаются.

«Попробовать ещё раз» появляется только при ошибке анализа или генерации.
Бот повторяет именно ту обработку, которая не удалась.

После нового текста, фото или файла бот отвечает новой карточкой в конце чата.
Сообщение об обработке и её результат используют эту же карточку. Предыдущие
ответы остаются в переписке; работают кнопки только последней карточки.
Карточка и её идентификатор сохраняются после перезапуска. Длинные описания
можно листать стрелками без новых сообщений. После просмотра изображения
текстовые экраны показываются в подписи с нейтральной полосой вместо чертежа:
Telegram не позволяет заменить сообщение с фото на обычный текст.
Если вы удалили карточку в Telegram, отправьте /menu для её восстановления.
Явные команды /start, /menu и /help отправляют меню новым сообщением в конце
чата, чтобы оно было видно сразу. Нажатия кнопок продолжают обновлять карточку
без новых сообщений. Кнопки старой карточки после новой команды неактивны.

Команды:

| Команда | Действие |
|---|---|
| /menu | Список последних 20 проектов |
| /new | Новый проект |
| /project | Данные текущего изделия |
| /retry | Повторить анализ сохранённых данных |

## Микросервисы

Бот общается с анализатором и генератором только через HTTP.
Анализатор получает описание, переписку и изображения, возвращает ответ
и уточнения. Он не хранит состояние и не читает чужие базы.
Его устройство: [services/dialogue/README.md](services/dialogue/README.md).

Генератор также самостоятельный. Сервис не импортирует aiogram,
не знает о Telegram и не открывает базу проектов бота. Вход содержит описание,
референсы, идентификатор проекта и версию. Выход содержит изображение и
привязку к той же версии. Данные передаются по контракту, а не общей папкой.

Генератор можно запустить отдельно:

```powershell
python -m pip install -r services/sketch/requirements.txt
python -m services.sketch.src.app
```

Его отдельный Dockerfile позволяет развернуть сервис без кода Telegram-бота.
Сервис хранит завершённые запросы по request_id, поэтому повторный запрос
той же версии возвращает сохранённое изображение. Для текущего этапа
запускается один экземпляр каждого процесса.

Настройки моделей независимы. Для OpenRouter: OPENROUTER_DIALOGUE_MODEL и
OPENROUTER_SKETCH_MODEL; в шаблоне openai/gpt-4.1-mini и openai/gpt-image-2.
Для прямого OpenAI: DIALOGUE_MODEL и SKETCH_MODEL. Доступ и баланс зависят
от выбранного аккаунта; качество пока не оценено на реальных эскизах.

## Docker — дополнительный вариант

После заполнения `.env`:

```powershell
docker compose up --build -d
```

Бот, анализатор и генератор работают в отдельных контейнерах. Бот и генератор
имеют отдельные тома данных; анализатор не нуждается в диске с проектами.
Каждый контейнер получает только свои настройки, бот не получает ключи AI.
Для остановки: `docker compose down`. Команда без `-v` сохраняет данные.
Docker для первого запуска в PyCharm не требуется.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют локальные заглушки внешних API, не вызывают платные модели
и не отправляют сообщения в Telegram. Живую проверку выполняйте по
[сценарию](docs/acceptance.md) после заполнения ключей.

# Двери и наполнение шкафа

Отсутствие двери на рукописном рисунке не означает, что её нет в изделии.
Бот уточняет невыясненные двери у отделений и скрытое за ними наполнение.
Отвечать можно обычным сообщением, в том числе по номерам вопросов.
Когда конструкция понятна, проверьте описание и подтвердите создание эскиза.

Генератор получает инструкцию показать один шкаф снаружи и изнутри,
условно скрывая двери на виде наполнения. Сохранённые результаты называются
«Эскиз №1», «Эскиз №2» и т.д.; сообщения с уточнениями не увеличивают этот номер.
Это пока эскизы без размерных линий. Размеры, в том числе размеры дверей,
будет наносить отдельный сервис на следующем этапе.

Промпт распознавания: `services/dialogue/prompts/analysis.md`;
проверка полноты: `services/dialogue/src/rules.py`;
промпт изображения: `services/sketch/prompts/sketch.md`. Новый промпт применяется
при следующем анализе/генерации, старые картинки автоматически не меняются.



## Раздельные настройки новых агентов

В `.env` поля `DIMENSIONS_TEXT_MODEL` и `DIMENSIONS_IMAGE_MODEL` задают модели
для уточнения и изображения с размерами. `RENDER_TEXT_MODEL` и
`RENDER_IMAGE_MODEL` — модели этапа рендеринга. Отдельные провайдер и ключ:
`DIMENSIONS_AI_PROVIDER`, `DIMENSIONS_API_KEY`, `RENDER_AI_PROVIDER`, `RENDER_API_KEY`.
Пустые поля наследуют действующие настройки OpenRouter/OpenAI и модели диалога/эскиза.
После изменения перезапускайте соответствующий сервис. Внутренние ключи сервисов
не являются API-ключами нейросетей.

Промпты новых агентов: `services/dimensions/prompts/analysis.md`, `image.md`
и `services/render/prompts/analysis.md`, `image.md`. Каждый сервис можно заменить
или запустить отдельно; взаимодействие идёт только по HTTP.
