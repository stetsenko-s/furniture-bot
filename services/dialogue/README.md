# Сервис dialogue — анализ и уточнение заявки

Одна задача: превратить текущие данные, переписку и изображения в обновлённое
описание изделия, ответ пользователю и список нерешённых вопросов.
Не отправляет сообщения в Telegram и не генерирует изображения.

Самостоятельный процесс, HTTP API, зависимости, Dockerfile, промпт и настройки
модели. Не импортирует `bot` или `services.sketch`, не открывает их базы.
Сервис не хранит состояние: бот передаёт нужный контекст с каждой заявкой.
Поэтому его можно перезапустить, не потеряв историю диалога.

## Запуск

Из корня репозитория:

```powershell
python -m pip install -r services/dialogue/requirements.txt
python run_dialogue.py
```

Либо `python -m services.dialogue.src.app`.
Настройки: `DIALOGUE_SERVICE_TOKEN`, `DIALOGUE_HOST` (127.0.0.1),
`DIALOGUE_PORT` (8092), `AI_PROVIDER` и ключ выбранного провайдера.
Модель: `OPENROUTER_DIALOGUE_MODEL` либо `DIALOGUE_MODEL`.
Настройки можно передать окружением отдельного процесса или контейнера;
общий `.env` нужен только для удобства локального запуска.
Ключ Telegram и доступ к данным бота не требуются.

## API

- `GET /health` — доступность процесса, без обращения к платной модели.
- `POST /v1/analyses`, заголовок `Authorization: Bearer <DIALOGUE_SERVICE_TOKEN>`.
- Вход `AnalysisRequest`: `contract_version=1`, `brief`, `messages`, `references`.
- Выход `AnalysisResponse`: `contract_version=1`, `result` с `brief`, `reply`,
  `questions` — уже проверенным списком строк.
- 401 — неверный внутренний ключ; 413 — запрос больше 60 МиБ;
  422 — неверный контракт; 502 — анализ провайдером не завершён.

HTTP API принимает только роли user/assistant. Изображения передаются как
base64, а не локальные пути. История целиком используется для прежней проверки
цитат; модель, как и раньше, получает последние 80 сообщений.
Автоматических повторов платного запроса нет.

## Файлы

- `src/app.py` — HTTP API, проверка доступа и связывание обработки.
- `src/provider.py` — обращение к OpenRouter/OpenAI.
- `src/models.py` — внутренняя структура ответа модели.
- `src/rules.py` — проверка дверей, наполнения и объединение вопросов.
- `prompts/analysis.md` — инструкции модели; после изменения перезапустите сервис.

Это выделение существующей логики. Новых этапов или правил распознавания нет.
